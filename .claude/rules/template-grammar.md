# Template Grammar

## When this applies

This rule applies when `project.json` has `"style": "proof-escalation-editorial"`. For `cinematic-presenter` and `editorial-authority`, the existing per-component selection in `component-mapping.md` continues to apply.

## What a template is

A **layout template** is a named configuration that controls 5 properties simultaneously:

1. **Avatar mode** — hidden, full-screen, bottom peek, overlays-on-body
2. **Split ratio** — content/avatar proportion (65/35, 50/50, 100/0, 0/100)
3. **Background** — warm-beige, dark, natural, content-driven
4. **Caption behavior** — headline, suppressed, section-label, badge-overlay, standard
5. **Template class** — ANCHOR (face-led) or PROOF (content-led)

These 5 properties are set together by selecting a template ID. Do not mix-and-match (e.g., suppressed captions with a split-screen avatar).

## Source of truth

Template definitions: `training/derived/template-registry.json`
Caption modes: `training/derived/caption-modes.json`
Rhythm bounds: `training/derived/rhythm-bounds.json`

These files are generated by `python training/derive_style_pack.py` from annotated training examples. As more reference reels are annotated, the registry grows and rhythm bounds widen.

## How template_id flows through the pipeline

```
shot-list (4b-i)    → assigns template_id per beat
shot-list (4b-ii)   → validates template constrains component choice
motion-intent (4c)  → references template_class for beat category
assembly (5)        → reads template_id → sets captionMode, splitRatio, avatarMode in timeline.json
QA (6)              → validates template_class oscillation, caption suppression, rhythm bounds
```

## Rules

### Template selection (Phase 4b-i)

Read `training/derived/template-registry.json`. For each beat:

1. What is the beat's **proof_class**? (existence, breadth, process, output, authority, cta, or null)
2. Which templates serve that proof class? (check `proof_classes_served` in registry)
3. Does the beat need the avatar visible? (direct address → ANCHOR template; proof content → PROOF template)
4. Select the template that matches both proof class and avatar need.

If no proof class (e.g., a bridge or transition beat), use `avatar-direct` or `avatar-overlay`.

### Template class oscillation (Phase 4b-i / QA)

Read `training/derived/rhythm-bounds.json` → `oscillation` section.

- Do not exceed `recommended_max_proof_run` consecutive PROOF templates
- Do not exceed `recommended_max_anchor_run` consecutive ANCHOR templates
- After a PROOF burst, insert an ANCHOR beat to reset viewer attention
- After an ANCHOR run, re-engage with PROOF content

### Caption suppression (Phase 5 / QA)

Read `training/derived/caption-modes.json` → `template_to_caption_mode` lookup.

When a template's caption mode is `suppressed`:
- Set `captionMode: "suppressed"` in the timeline.json entry
- The composition must NOT render caption text during this entry's time range
- Reason: the visual already contains readable text (UI, cards, documents)

### Split ratio (Phase 5)

Read the template's `split_ratio` from the registry.

| Ratio | Content zone | Avatar zone |
|---|---|---|
| 50/50 | top 50% | bottom 50% |
| 65/35 | top 65% | bottom 35% (head peek) |
| 100/0 | full frame | avatar hidden |
| 0/100 | none | avatar full-screen |
| 40/60 | top 40% | bottom 60% (standard, not used in this style) |

Set `splitRatio` in the timeline.json entry. Assembly reads this instead of hardcoding 40/60.

## When NOT to use templates

- If the style is `cinematic-presenter` or `editorial-authority`, use existing per-component selection
- If a beat genuinely doesn't fit any template (rare), fall back to per-component selection and document why
- Do not build new templates preemptively — only add to the registry when a new reference reel demonstrates a pattern not covered by existing templates
